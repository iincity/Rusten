# Rusten MVP 验收门禁

## 已自动验证

- Rust 核心路径、规则、P0/P1/P2/P3 准入、链接和文件身份测试通过；
- 默认清理计划只接受 `quick + P3 + high confidence + recycle/backup`，且执行前重新验证；
- 管理员助手协议为固定枚举、限长帧、请求 ID、当前用户 ACL 和调用方 SID 校验；
- 操作日志、备份索引、恢复目标冲突和离线配置写入具备单元测试；
- 默认代码路径不创建网络客户端，遥测和远程能力尚未进入 MVP 依赖。
- GPUI 和 CLI 通过 `FastFileScanner` 扫描；默认 feature 已启用固定提交的 UFFS MFT 索引转换，权限、卷或索引失败时回退 Win32。结果和规则候选仍汇总到同一份 `ScanIndex`。
- UFFS 只负责快速索引和路径发现，不负责清理决策；重解析点、路径边界、文件身份和执行前元数据复核继续由 Rusten 适配层及清理层负责。

## NTFS 扫描基线

2026-09-25 在本机临时 NTFS 目录执行单次扫描基线，测试后已删除 fixture：

| Fixture | 文件 | 目录 | 扫描耗时 | 警告 |
| --- | ---: | ---: | ---: | ---: |
| 100k | 100,000 | 1,001 | 29,348 ms | 0 |
| 1M | 1,000,000 | 1,001 | 227,342 ms | 0 |

该结果是扫描器单次基线，不替代不同硬件上的内存、CPU、UI 响应 P50/P95/P99 发布验收。

性能测试会在 Windows 上额外输出 `cpu_ms` 和 `peak_working_set_mib`，分别表示扫描期间进程 CPU 时间增量和进程峰值工作集。示例运行方式：

```powershell
$env:RUSTEN_PERF_FIXTURE_ROOT = 'D:\RustenPerf100k'
cargo test -p platform-windows --test performance_scan_tests -- --ignored --nocapture one_hundred_thousand_file_scan_baseline
```

扫描事件通过容量受限的 `sync_channel` 传递，并由消费者并发消费，避免百万文件扫描将事件无限堆积在内存中。未设置性能 fixture 环境变量时，性能测试显式失败，不得以跳过或空结果替代测量。

GPUI 运行时采集事件分发和渲染延迟，保留有界样本并提供 P50/P95/P99 快照测试；这些指标需要在目标硬件和真实界面交互下重复采样。

扫描耗时、CPU、内存和 GPUI 响应仍需在目标硬件上重复采样，计算 P50/P95/P99 后才能作为发布门禁；单次测试不会伪造这些分位数。

## 发布前必须在真实 NTFS 环境完成

- 100,000/1,000,000 文件扫描耗时、内存、CPU、UI 响应的 P50/P95/P99 基线；
- 长路径、特殊字符、硬链接、Junction、锁定文件、拒绝访问目录和只读磁盘；
- 普通用户与管理员权限矩阵，以及 UAC 拒绝后的安全回退；
- 回收站/备份恢复、冲突处理、取消、重启和磁盘空间不足；
- 默认禁止路径拦截率 100%，默认运行无网络请求。

## 阻断条件

任一 P0 缺陷、不可解释的失败项、不可恢复的已处理文件、浏览器登录态误删、绕过 UAC 或直接删除系统组件目录，均不得进入 MVP+。
