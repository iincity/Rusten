# C 盘清理工具架构设计方案

## 1. 设计目标

本项目定位为 Windows C 盘空间分析、可审计清理和恢复治理工具，核心闭环为：

```text
看清空间 -> 理解原因 -> 生成清理预览 -> 安全执行 -> 可恢复和可审计
```

设计目标：

- 使用 Rust 构建扫描、规则、清理、恢复和审计核心；
- 使用 `gpui` + `gpui-component` 构建简洁桌面界面；
- 普通扫描和用户目录操作不要求管理员权限；
- 系统目录操作通过按需启动的管理员助手执行；
- 目录树、大文件列表和清理列表共享同一个扫描索引；
- 默认一键清理只处理低风险、高置信度、可恢复项目；
- 默认离线，不上传文件名、路径、文件内容和用户行为数据；
- 高风险动作必须经过独立确认、恢复前置条件和完整审计。

## 3. 分层设计

### 3.1 表现层

位置：`apps/cleaner-ui`

职责：

- 组织 GPUI 页面和组件；
- 展示磁盘总览、扫描进度和结果；
- 展示目录树、大文件列表和可清理项；
- 发出扫描、清理、恢复、导出等用户命令；
- 处理确认弹窗、权限提示和错误状态；
- 将领域事件转换为 UI 状态。

禁止：

- 直接调用 Windows API；
- 直接删除或移动文件；
- 直接执行 PowerShell、DISM 或 winget；
- 在 UI 中实现风险判断和规则准入。

UI 只发送类型化命令，例如：

```text
StartScan
PauseScan
ResumeScan
CancelScan
ExpandDirectory(node_id)
CreateQuickCleanPreview
ExecuteCleanup(plan_id)
RestoreOperation(operation_id)
ExportReport(format)
```

### 3.2 应用层

位置：`crates/application`

职责：

- 编排扫描、清理、恢复和报告用例；
- 管理后台任务、取消和进度；
- 调用领域服务完成规则判断；
- 通过 Port 调用平台和持久化能力；
- 将结果转换为 UI 可消费的事件。

核心服务：

```text
ScanService
CleanupService
RecoveryService
RuleService
ReportService
ConfigService
```

应用层不依赖 GPUI，不直接依赖具体 Windows API 实现。

### 3.3 领域层

位置：`crates/domain`

职责：

- 文件、目录、卷和扫描状态模型；
- 目录大小和磁盘占用聚合；
- Top-N 大文件索引；
- 规则匹配和分类；
- P0-P3 风险判断；
- 白名单、禁止路径和链接边界判断；
- 一键清理准入；
- 清理计划和结果模型；
- 恢复状态和审计对象。

领域层保持纯 Rust，不能依赖：

- `gpui`；
- Windows API；
- SQLite；
- PowerShell；
- 真实文件系统。

这样可以用普通 Rust 单元测试覆盖安全策略和规则逻辑。

### 3.4 Windows 平台层

位置：`crates/platform-windows`

职责：

- 文件系统枚举和元数据读取；
- 长路径、重解析点、硬链接和 Junction 处理；
- 文件锁和进程状态检测；
- 回收站和 Shell 文件操作；
- 磁盘容量读取；
- 浏览器和应用进程检测；
- DISM、PowerShell、Windows Update 和 winget 封装；
- 管理员助手客户端。

平台层只提供事实和执行能力，不决定业务风险等级。

### 3.5 持久化层

位置：`crates/persistence`

持久化内容：

- 用户配置；
- 清理操作日志；
- 备份文件索引；
- 恢复记录；
- 报告元数据；
- 数据库迁移版本。

完整扫描结果默认只存在内存中，不永久保存，避免数据库持续膨胀和隐私泄漏。

## 4. 核心模块设计

### 4.1 文件系统扫描模块

MVP 使用 Windows 文件枚举 API：

- `FindFirstFileExW`；
- `FindNextFileW`；
- `GetFileInformationByHandle`；
- `GetDiskFreeSpaceExW`。

扫描流程：

```text
读取卷容量
  -> 规范化扫描根路径
  -> 枚举目录项
  -> 读取文件元数据
  -> 检查链接和硬链接
  -> 更新目录聚合
  -> 更新 Top-N 大文件
  -> 匹配清理规则
  -> 发送增量扫描事件
```

USN Journal 不作为 MVP 首次全量扫描的唯一实现。后续可用于增量扫描和变更检测。

### 4.2 扫描索引模块

目录树、大文件列表和清理列表必须共享同一份 `ScanIndex`：

```text
ScanIndex
├── root_volume
├── directory_arena
├── directory_lookup
├── top_files_heap
├── cleanup_candidates
├── extension_statistics
├── scan_statistics
└── warnings
```

扫描索引原则：

- 目录节点保留完整树结构；
- 大文件只保留 Top-N，例如 Top 1000；
- 清理候选只保留命中规则的对象；
- 不为不同 UI 视图重复枚举磁盘；
- 逻辑大小和实际磁盘占用分别统计。

### 4.3 文件身份和链接处理

文件不能只用路径识别，至少使用：

```text
VolumeSerialNumber + FileIndex
```

路径用于规则匹配和显示，文件身份用于硬链接去重和删除前复核。

默认策略：

- 不跟随符号链接；
- 不跨卷进入 Junction 或挂载点；
- 不进入网络路径；
- 同一硬链接只统计一次物理占用；
- 检测到循环立即终止当前分支；
- 所有跳过原因进入扫描警告。

### 4.4 规则模块

规则使用声明式 TOML。规则负责识别候选对象，安全策略负责决定对象是否可执行。

```toml
id = "browser.edge.cache"
name = "Microsoft Edge 缓存"
category = "browser_cache"
mode = "quick"
risk = "P3"
confidence = "high"
recovery = "recycle"

processes = ["msedge.exe"]

[match]
paths = ["%LOCALAPPDATA%/Microsoft/Edge/User Data/*/Cache/*"]

[exclude]
paths = [
  "*/Login Data",
  "*/Cookies",
  "*/Web Data",
  "*/Bookmarks",
  "*/Extensions"
]

warning = "删除后浏览器会重新生成缓存"
```

规则最少包含：

```text
id
name
category
mode
risk
confidence
paths
exclude_paths
processes
minimum_os
recovery
requires_admin
warning
version
```

MVP 只使用内置规则。签名规则包、远程规则更新和灰度发布放到 1.0。

### 4.5 风险和准入模块

风险等级：

```text
P0 Forbidden          禁止操作
P1 SystemCritical     系统关键项，需高级确认
P2 UserData           用户数据，只发现或显式确认
P3 RebuildableCache   可重建缓存，可进入一键模式
```

一键清理准入条件必须全部满足：

```text
rule.mode = quick
risk = P3
confidence = high
recovery = recycle 或 backup_then_delete
locked = false
path_allowed = true
file_identity_unchanged = true
```

任何不确定状态按保留处理。

硬编码禁止项优先级最高，普通用户配置不能解除 P0 禁止项。

### 4.6 清理执行模块

清理流程：

```text
扫描候选
  -> 规则准入
  -> 用户预览
  -> 用户确认
  -> 重新验证路径和文件身份
  -> 检查锁定状态
  -> 回收站或备份
  -> 执行移动/删除
  -> 验证结果
  -> 写入操作日志
```

执行前重新检查：

- 文件是否仍存在；
- 文件大小和修改时间是否变化；
- 文件身份是否变化；
- 是否被进程占用；
- 是否命中禁止路径；
- 是否仍满足当前规则。

结果类型：

```text
Deleted
MovedToRecycleBin
BackedUp
SkippedLocked
SkippedPermission
SkippedChanged
SkippedForbidden
Failed
```

### 4.7 恢复模块

恢复方式：

```text
recycle
backup_then_delete
delete_only
shred_once
```

MVP 默认只使用 `recycle` 和 `backup_then_delete`。

每次操作至少记录：

```text
operation_id
rule_id
original_path
current_path
file_identity
size
hash（可选）
backup_id
recycle_bin_id（可选）
timestamp
result
error_code
```

恢复时：

- 原路径可写则恢复到原路径；
- 存在冲突则提示覆盖、跳过或另存为；
- 原路径不可用则允许选择新目录；
- 批量恢复逐项记录结果。

### 4.8 管理员助手模块

主界面以普通用户权限运行，仅在访问受限目录或执行系统维护时启动 `admin-helper.exe`。

```text
cleaner-ui.exe
       │ Named Pipe
       ▼
admin-helper.exe
       │
       ├── 系统临时目录
       ├── 回收站
       ├── DISM
       ├── 系统还原点
       └── VSS
```

管理员助手只接受固定操作枚举，不接受任意命令字符串、脚本字符串或用户传入的可执行路径。

安全要求：

- Named Pipe 使用当前用户 ACL；
- 请求包含请求 ID 和操作类型；
- 助手再次校验路径、权限和风险；
- 助手不加载用户可编辑规则；
- 助手不联网；
- 每次任务结束后退出，不常驻。

## 5. GPUI 界面设计

### 5.1 视觉参考

主界面参考：`docs/参考/c3372dc5-9c71-4345-ab1c-639365467997.png`

参考图采用“功能导航 + 扫描状态 + 分类网格”的桌面工具布局。本项目沿用其信息组织方式，但将文案、风险等级和操作语义改为本产品的“空间分析与受控清理”，不复制其自动清理和高风险项目的默认行为。

### 5.2 主界面布局

```text

│ 品牌/产品名   │ 扫描状态标题       自动清理开关   设置       │
```

### 5.3 左侧导航

左侧导航保持固定宽度，负责模块切换，不承载清理逻辑：

| 导航项 | 内容 | MVP |
|---|---|---|
| 首页 | C 盘容量、占用率、可释放空间和最近结果 | 是 |
| C 盘概览 | 扫描状态和主要空间类别 | 是 |
| 空间分析 | 目录树和大文件列表 | 是 |
| 可清理项 | 按规则分类的清理候选 | 是 |
| 大文件 | 大文件筛选和路径定位 | 是 |
| 重复文件 | 重复文件候选 | MVP+ |
| 恢复记录 | 已删除、已备份和可恢复项目 | 是 |
| 设置 | 扫描范围、排除项、备份和隐私 | 是 |

导航项可以显示数量或大小摘要，但不能使用红色告警制造紧迫感。P0/P1 风险项目只显示风险标识，不进入默认一键清理。

### 5.4 顶部扫描状态区

顶部状态区始终可见，解决参考图中“用户不知道是否仍在扫描”的问题：

- 状态：未扫描、扫描中、已暂停、已完成、已取消、失败；
- 当前扫描路径或阶段；
- 已扫描文件数、已发现空间和预计剩余时间；
- 进度条；
- 重新扫描；
- 暂停/继续；
- 停止扫描；
- 按需显示自动清理开关。

自动清理开关默认关闭。开启后只允许触发 P3、高置信度、可恢复规则，且仍需在清理前展示摘要并要求确认。

### 5.5 中央清理分类网格

清理分类网格是首页和可清理项页的核心内容，适合参考图中的“一眼看懂”布局。每个分类项包含：

```text
图标
分类名称
命中文件数量
预计释放空间
风险等级
选择框
详情入口
```

MVP 分类：

- 系统临时文件；
- 当前用户临时文件；
- 浏览器缓存；
- 应用可重建缓存；
- 缩略图缓存；
- 错误报告和可重建日志；
- 回收站。

默认不以网格卡片展示或选择以下项目：

- 用户文档、下载、图片、视频和代码仓库；
- 浏览器密码、Cookie、登录态和主数据库；
- 邮件、聊天和应用业务数据库；
- WinSxS、Windows Update 内部目录和系统组件；
- 休眠文件、系统还原点、VSS 快照；
- 大文件、旧文件和重复文件。

分类项的可选状态：

```text
Disabled       不可用或未扫描
Available      可查看但未选择
Selected       已进入预览队列
Blocked        被风险策略阻止
RequiresClose  需要关闭相关应用
```

### 5.6 底部操作区

底部操作区固定显示当前选择的执行摘要：

- 已选择类别数量；
- 预计释放空间；
- 可恢复方式；
- 被锁定或跳过项目数量；
- `查看详情`；
- `生成预览`；
- `一键清理`。

`一键清理`不是立即删除。点击后先进入确认视图，显示分类、规则原因、风险、预计释放空间、恢复方式和需要关闭的应用。

### 5.7 页面职责

首页：

- C 盘总容量、已用空间、剩余空间；
- 可安全释放空间；
- 当前扫描状态；
- 分类清理网格；
- 一键清理入口。

空间分析页：

- 逐级目录空间树；
- 大文件清单；
- 阈值筛选；
- 复制路径；
- 打开所在目录；
- 从大文件跳转到目录树。

可清理项页：

- 按类别显示候选项；
- 文件数量和预计释放空间；
- 风险和恢复方式；
- 规则原因和警告；
- 选择、预览和确认。

恢复记录页：

- 操作时间；
- 清理类别；
- 原始路径；
- 备份/回收站位置；
- 恢复状态；
- 单项或批量恢复。

### 5.8 界面状态

#### 扫描中

- 顶部使用明确的扫描状态和进度条；
- 中央分类项实时更新已发现空间；
- `停止扫描`只停止扫描，不触发清理；
- 已完成的目录可以浏览，未完成目录标记为“扫描中”；
- 不显示虚假的最终可释放空间。

#### 扫描完成

- 顶部显示扫描完成和扫描耗时；
- 分类项显示大小、数量和风险；
- 默认只勾选符合一键清理准入的 P3 项；
- 大文件和用户数据保持未选中；
- 底部显示预计释放空间和查看详情入口。

#### 清理确认

- 展示清理类别和规则原因；
- 展示预计释放空间和恢复方式；
- 展示被锁定、权限不足和需要关闭的应用；
- 明确标识不可恢复动作；
- 用户确认后才执行。

#### 清理完成

- 实际释放空间；
- 成功、跳过和失败数量；
- 锁定文件和权限失败；
- 已备份项目；
- 可恢复项目；
- `查看恢复记录`和`再次扫描`。

### 5.9 视觉和交互约束

- 界面以浅色中性背景、低饱和绿色状态色和蓝色主操作色为主；
- 绿色只表示安全、完成或可恢复，不表示所有项目都可删除；
- 红色仅用于禁止项、不可逆操作和错误；
- 分类图标使用统一图标库，不使用 Emoji；
- 图标按钮必须有悬停提示和键盘可访问名称；
- 卡片圆角不超过 8px，避免嵌套卡片；
- 大文件列表和目录树使用虚拟列表；
- 路径过长时折叠显示，悬停展示完整路径，支持复制；
- 扫描、删除和恢复期间所有按钮都有明确禁用或进行中状态；
- 清理动作提供键盘导航、焦点状态和高对比度文本；
- 不使用动画掩盖扫描延迟，动效只用于状态切换和进度反馈。

Treemap 属于 P1 功能，在目录树、大文件和清理闭环稳定后增加。

## 6. Workspace 目录结构

```text
ruste-cleaner/
```

## 7. 模块依赖约束

```text
cleaner-ui -> application -> domain
application -> platform-windows
application -> persistence
admin-helper -> domain
admin-helper -> platform-windows
```

约束：

- `domain` 不依赖 UI、Windows API、SQLite；
- `application` 不依赖 GPUI；
- `platform-windows` 不包含业务风险决策；
- `persistence` 不决定清理权限；
- UI 不持有删除逻辑；
- 管理员助手不执行任意命令。

## 8. 分阶段实施

### MVP

- C 盘容量总览；
- 目录空间树；
- Top 大文件；
- 扫描暂停、恢复和取消；
- 系统临时文件、回收站和浏览器缓存；
- 风险分类和一键清理预览；
- 回收站/备份区恢复；
- 操作日志；
- GPUI 主界面；
- 管理员助手基础通信。

### MVP+

- 大文件、旧文件和重复文件发现；
- 应用清单和受控卸载；
- Windows Update 和 DISM；
- WinSxS 只读分析和受控清理；
- VSS、系统还原点和备份配额；
- HTML、CSV、JSON 报告；
- 可选覆写。

### 1.0

- 企业策略和审批；
- CLI 和计划任务；
- 启动项、服务、计划任务只读面板；
- 远程只读管理；
- 遥测平台；
- 产品和规则自动更新；
- 签名规则、灰度发布和回滚；
- 企业审计和远程诊断。

1.0 的远程能力不能绕过本地安全策略，远程清理不能默认变成远程永久删除。

## 9. 验收重点

至少覆盖：

1. 长路径；
2. 符号链接、Junction 和循环；
3. 硬链接重复统计；
4. 文件锁定；
5. 权限不足；
6. 扫描取消和恢复；
7. 扫描后文件发生变化；
8. 回收站恢复；
9. 管理员助手通信；
10. P0 禁止路径不会进入默认清理队列。

目标指标：

- 100 万文件扫描不超过 10 分钟；
- UI 不出现超过 1 秒的阻塞；
- 10 万目录节点支持正常滚动和展开；
- 默认禁止项拦截率 100%；
- 默认运行无网络请求；
- 每个清理动作均记录规则 ID、路径、大小、备份 ID、时间和结果。
