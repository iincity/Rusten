技术栈要求：
1.采用RUST语言进行开发；
2.界面采用gpui + gpui-component
3.要求界面简洁，操作简单。结果一目了然

## 产品分阶段规划

### MVP

MVP 只实现本地可信扫描与可恢复清理闭环：

- C 盘容量总览、目录空间树和大文件列表；
- 系统临时文件、回收站、浏览器缓存和明确可重建应用缓存；
- 清理预览、风险分级、回收站/备份区恢复和操作日志；
- 普通用户进程与按需启动的管理员助手进程；
- 默认离线，不上传扫描路径、文件名、文件内容和用户行为数据。

### MVP+

在 MVP 稳定后增加：

- 大文件、旧文件和重复文件发现；
- 应用清单、受控卸载；
- Windows Update、DISM、WinSxS 的只读分析和受控清理；
- VSS/系统还原点、备份配额和 HTML/CSV/JSON 报告；
- CLI 和计划任务，但计划任务默认只扫描和生成报告，不自动删除。

### 1.0 企业治理能力

1.0 将远程管理、遥测平台和自动更新服务作为独立的企业治理能力建设，不能改变本地清理的安全边界。

#### 远程管理

目标是提供受控的设备管理和远程诊断，而不是远程擦盘：

- 管理员可下发签名策略、扫描范围、排除项和维护时间窗；
- 支持远程发起只读扫描、获取脱敏报告和查看执行结果；
- 远程清理必须由设备端用户或本地审批明确确认；
- 禁止默认支持远程永久删除、远程关闭安全机制和任意命令执行；
- 每次会话记录设备、管理员、策略版本、审批人、时间和结果；
- 支持离线导入导出策略，网络不可用时本地核心功能仍可用。

推荐模块：

```text
remote-management/
├── device-identity
├── policy-sync
├── readonly-command
├── approval
└── audit-upload
```

#### 遥测平台

遥测默认关闭，用户版和企业版均不得以遥测作为本地功能的前置条件。开启后只采集最小化的产品运行指标：

- 扫描耗时、文件数量区间、清理结果类别和错误码；
- 产品版本、系统版本、架构和匿名设备标识；
- 不上传完整路径、文件名、文件内容、浏览器数据、用户名和原始哈希；
- 支持企业管理员配置采集范围、保留期限和数据驻留区域；
- 支持本地脱敏、传输加密、用户撤回授权和数据删除；
- 崩溃报告默认本地生成，上传前必须由用户或管理员明确授权。

推荐模块：

```text
telemetry/
├── event-model
├── consent
├── redaction
├── local-buffer
├── transport
└── retention
```

#### 自动更新服务

自动更新只负责本产品程序、内置规则和签名配置，不负责第三方软件升级，也不把更新行为混入清理流程：

- 更新包、规则包和配置包必须签名并校验哈希；
- 支持版本兼容检查、灰度发布、暂停发布和回滚；
- 默认提示用户确认，企业策略可配置维护窗口；
- 更新失败不能破坏已有版本、清理日志和恢复索引；
- 规则更新失败时继续使用最近一次已验证版本；
- 更新服务不得下载或执行未在允许清单中的程序。

推荐模块：

```text
updater/
├── manifest
├── signature
├── download
├── staged-install
├── rollback
└── rollout-policy
```

### 规划边界

远程管理、遥测平台和自动更新服务均不进入 MVP 的核心依赖，避免网络、账号或服务端故障影响本地扫描、清理和恢复。1.0 前置条件包括：

1. 本地扫描准确性、清理安全性和恢复链路通过验收；
2. 管理员助手通过权限、通信和注入安全测试；
3. 所有远程策略、遥测事件和更新包具备版本、签名、审计和回滚机制；
4. 企业功能具备明确的授权、数据保留、数据删除和离线降级策略。
