# 深度 C 盘清理工具功能需求调研

## 摘要：产品应成为可信赖的“C 盘空间决策系统”，而不是又一个激进的系统优化器

截至 2026 年 9 月 24 日，主流产品已清晰分成四类专业工具：TreeSize、WinDirStat 专注可视化分析；BleachBit 专注规则化文件与痕迹清理；PrivaZer 专注隐私残余和不可逆擦除；Patch My PC Home Updater 专注第三方应用补丁 [1][3][4][5]。因此，本产品应定位为“Windows C 盘空间分析、可审计清理与恢复治理工具”，而不是覆盖系统优化、驱动更新、内存调优、杀毒或软件安装的全能工具。

推荐架构是 Rust 核心引擎加独立管理员助手进程，以 Windows API、USN/NTFS 枚举、WMI/CIM 和 Windows 服务封装处理扫描、链接解析、去重和安全边界；浏览器与应用缓存、注册表、启动项、任务计划等易变规则使用声明式配置；WinSxS、系统还原、功能与组件清理优先调用 DISM；应用识别、升级和卸载调用 winget；维护任务复用 PowerShell。Rust 非常适合跨配置、CLI、规则解释、增量扫描和日志流水线，但无需重写整个 Windows 栈。

立项建议采用 MVP—MVP+—1.0 三阶段：MVP 只交付只读空间分析、可解释扫描预览、默认一键清理、系统临时文件清理、回收站、浏览器与应用缓存分类，以及可撤销删除；MVP+ 增加重复文件、大/旧文件、WinSxS 受控清理、备份恢复和报告导出；1.0 才增加企业策略、远程审计、计划任务和灰度清理。

**默认一键清理不是“扫描到什么就删什么”，而是由产品替用户完成规则准入、风险判断和结果兜底。** 一键模式只执行高置信度、低风险、可恢复且不涉及用户文档或系统组件依赖的清理项；普通用户无需逐项判断，但引擎仍须逐条核验路径、年龄、文件锁、链接目标、系统状态和恢复方式。1.0 默认不得执行永久删除、休眠关闭、SSD 全盘覆写、注册表深度清理、系统还原点删除或第三方软件批量升级；这些操作均需要独立开关、专家模式或企业策略，并强制二次确认。

## 1. 产品应把“判断权”保留给用户，而不是用激进清理制造虚假的性能提升

**本产品首先是一个帮助 Windows 用户理解 C 盘占用、识别可恢复空间并安全执行删除的工具。** 它的商业差异化不是“清理项最多”，而是结果可解释、操作可回滚、规则可审计，且不会把系统优化、应用补丁、隐私擦除混成一组危险的一键操作。

TreeSize 的核心价值是饼图、条形图、Treemap、扩展名统计、大文件视图、报告导出、重复文件查找和计划任务；WinDirStat 同样以磁盘使用分析、多线程/NTFS 直接扫描、交互式 Treemap 和扫描导出为核心 [2][3]。BleachBit 则强调按应用枚举可清理项、白名单、可选文件粉碎和命令行自动化 [1]；PrivaZer 进一步聚焦活动痕迹、深度清理和按存储介质适配的覆写技术 [4]；Patch My PC Home Updater 的核心是更新和卸载第三方应用，而不是清理缓存 [5]。

竞品分工说明，本产品不需要重复实现一个更花哨的 Treemap，也不需要宣称比 DISM 更懂 Windows 组件。真正应补上的缺口，是让“空间为什么被占用—哪些可以安全清理—会产生什么后果—如何撤销”形成闭环。

**产品不做“性能优化器”。** 默认一键清理只处理“空间释放”，不处理性能调优；它以普通用户无需专业判断为目标，但不承诺“自动解决所有磁盘空间问题”。首期不得把禁用服务、修改电源计划、删除 Prefetch、清除 DNS 缓存、修改网络参数、调整视觉效果、修改注册表瘦身或“加速开机”列入 KPI。即使后续 1.x 提供启动项查看，也只是把启动项、计划任务、服务、应用后台任务和对应资源占用显示出来，默认不提供一键禁用。Dism++ 公开界面中大量系统优化、驱动管理和部署能力，恰恰应被视为高风险能力域，而不是默认复制对象 [6]。

默认一键清理的目标用户是“无法判断某个目录能否删除”的普通用户，产品替其完成判断；但它不等于隐藏清理结果。用户必须能够看到预计释放空间、主要类别、实际释放空间、失败项和查看详情入口。一键模式只勾选 P3 低风险和经规则确认为高置信度且可恢复的项目；P2 用户数据默认不勾选，P1 系统关键项目和 P0 禁止项目不得进入一键队列。

**产品不做自动安全擦除套件。** PrivaZer 的擦除能力包括覆写活动痕迹和识别存储介质类型 [4]；BleachBit 提供文件粉碎及空闲空间覆写 [1]。本产品可以提供“移至回收站—回收站清空—备份区保留—可选单次覆写”的分级删除，但不得把“覆写”设为默认。SSD 的覆写收益有限，且会增加写入磨损；企业数据销毁需求应通过微软 BitLocker、加密擦除或符合自身规范的企业介质销毁流程解决。

**产品不做软件商店或补丁服务器。** Patch My PC Home Updater 可自动更新 500 多个应用并提供静默安装、批量卸载和计划更新 [5]；本产品仅读取已安装程序清单、检测更新可用性、调用 winget 执行安装/升级/卸载，并在失败或退出码异常时保留日志。应用更新默认关闭，不得捆绑任何安装包，也不得把“应用升级”计入“清理释放空间”。

### 1.1 明确不做清单

| 能力 | 立项判断 | 理由与触发条件 |
|---|---|---|
| 一键优化、全能加速、驱动更新 | 不做 | 与 C 盘空间无直接关系，误禁用服务、电源策略和网络设置风险高 |
| 注册表深度清理、无效项批量删除 | 默认不做；1.0 以后可作为只读检查和专家模式候选 | 空间收益通常很小，错误删除可能导致软件或系统失效 |
| Prefetch、Superfetch 文件批量删除 | 不做 | 属于系统运行数据，清理没有稳定性能收益，反而可能影响启动诊断 |
| 自动禁用休眠、删除 hiberfil.sys | 不做默认项 | 需确认设备类型、电池策略、恢复要求和用户意图 |
| CompactOS、系统压缩 | 不做默认项 | 需要按 I/O 负载、CPU、SSD 寿命和企业策略评估；仅显示影响并调用 DISM |
| 自动关闭系统还原或删除所有还原点 | 不做 | 会直接破坏后续回滚能力；仅允许查看和创建还原点 |
| 永久删除、清空空闲空间、DoD 级擦除 | 不做默认项 | 不属于常规空间清理；SSD 可能无效或有害，应作为可选治理动作 |
| 自动删除下载、文档、图片、视频、虚拟机、代码仓库、游戏、邮件和聊天文件 | 不做 | 这些可能是工作成果或唯一副本，仅支持按大小、年龄和排除规则发现 |
| 自动卸载 Office、Visual Studio、SQL Server、驱动、杀毒软件、Microsoft Store 应用 | 不做 | 属于业务连续性决策；仅提供清单、占用、上次使用时间和卸载入口 |
| 修改 UAC、组策略、Defender、防火墙、Edge/Chrome 安全设置 | 不做 | 安全机制不得被“清理”绕过 |
| 自动安装 winget、NuGet、MSIX 或第三方包 | 不做 | 安装源、许可和退出码必须由管理员确认；默认只审计和更新 |
| 收集设备标识、文件内容、扫描路径全文或匿名遥测 | 默认不做 | 扫描数据本身可能包含隐私；默认必须完全离线、可选择本地诊断包 |
| 企业远程命令、静默批量擦除、自动加密或勒索防护 | 不做个人版；1.0 以后限定在受管企业模式 | 需要独立授权、设备身份证明、审批日志和明确回滚机制 |

## 2. 能力域必须按“看、扫、清、回、管”分层，任何高风险操作都不能跳过解释和审批

**用户价值来自“看清楚—看懂—再决定”，而不是按扩展名批量删除。** 每个能力域都应有独立数据源、风险等级、权限边界和撤销路径；若某个动作无法解释，就不应出现在常规清理清单中。

空间分析回答“空间在哪里”；系统垃圾清理回答“哪些数据可以重算或重新生成”；隐私清理回答“删除后是否仍能从残余位置恢复”；恢复与安全回答“出错或想撤销时怎么办”；管理回答“能否在企业中受控复制”。WinDirStat 的 Treemap 用矩形面积表示文件大小、颜色表示文件类型、嵌套表示目录结构，适合作为“看清”的能力基线 [3]；TreeSize 的报告、过滤、重复文件和阈值告警，则适合作为“看懂和汇报”的基线 [2]。

### 2.2 统一操作模型

每项候选对象都应生成“事实、判断、风险、动作”四层结果。事实包括路径、卷、大小、占用、最后访问或修改时间、属性、链接类型、锁定进程、来源规则和应用归属；判断包括可回收、不可回收、重复、冷数据或风险；风险分为 P0 禁止、P1 系统关键需二次确认、P2 用户数据需确认、P3 普通缓存默认可清理；动作则包括忽略、移入回收站、移入备份区、删除、清空、覆写、卸载、创建还原点或创建 VSS 快照。

规则必须采用声明式配置，至少包含规则 ID、显示名、支持版本、路径/通配符、正则、文件年龄、文件大小、锁定策略、应用进程、依赖项、回滚策略、风险等级、警告文案和来源链接，以及适用的操作模式。规则数据库可以离线导入，但不应默认从公网自动拉取不受签名控制的第三方规则。BleachBit 的自动导入扩展规则说明规则生态有价值，同时也放大来源可信度风险，因此本产品必须以签名、哈希和允许清单约束规则来源 [1]。

一键模式必须遵循统一准入策略：只有“对象类型已识别、路径已规范化、规则原因可解释、风险等级为低风险、置信度为高、动作可逆、当前未被系统或用户进程锁定、未命中禁止路径”的项目才能加入默认队列。判断变量包括路径、文件年龄、文件大小、硬链接/符号链接/Junction、卷边界、应用进程状态、系统更新状态、规则来源和当前产品模式。一键模式不得只依赖扩展名，也不得通过降低风险等级把用户文件伪装成可自动清理项。

### 2.3 三种操作模式

| 模式 | 目标用户 | 默认行为 | 可见范围 | 执行门槛 |
|---|---|---|---|---|
| 默认一键清理 | 不熟悉系统目录的普通用户 | 自动扫描并自动清理已准入的高置信度低风险项 | 类别摘要、预计/实际释放空间、失败项 | 用户点击主按钮，但不要求理解路径与系统组件 |
| 标准清理 | 希望参与选择的用户 | 显示 L1/L2 缓存、系统受控项及部分提示项 | 类别、数量、大小、风险标签 | 逐项勾选后执行 |
| 高级/专家清理 | 有经验的用户 | 开放系统组件、还原、休眠等高风险维护项 | 路径、规则原因、依赖、系统状态 | 独立开关、风险提示、二次确认及必要的恢复前置条件 |

一键模式应成为首屏默认入口，标准清理和高级清理分层展示。产品不得用“一键优化”“极速加速”“深度清理”等模糊名称掩盖操作差异。

## 3. MVP 只验证核心闭环，不追求扫描项数量或“一键释放空间”

**MVP 的最小可交付成果，是让用户能够安全地看懂 C 盘、识别普通临时缓存、预览删除结果并撤销错误操作。** 此阶段的价值在于证明扫描准确、删除安全和审计完整，而不是证明产品支持最多清理项。

### 3.1 MVP 需求清单

| 编号 | 功能 | 优先级 | 用户价值 | 技术可行性与实现选择 | 主要风险 | 验收标准 |
|---|---|---|---|---|---|---|
| A1 | C 盘分区总览 | P0 | 快速判断系统盘是否紧张，并显示扫描范围、容量、可用空间、占用率和扫描状态 | Rust：`GetDiskFreeSpaceExW`、长路径 `\\?\`、USN/FindFirstFile 双模式 | 长路径、权限拒绝、链接循环 | 与资源管理器按同一簇大小口径核对；容量、可用空间、已用空间自洽；100 万个文件扫描在消费级 SSD 上不超过 10 分钟 |
| A2 | 逐级钻取式目录空间树 | P0 | 未展开时从宏观比较主要目录，展开后逐级定位到具体子目录或文件；一级目录大小构成分区总览的空间构成 | Rust 增量扫描、目录聚合、虚拟滚动、展开状态保持；同时维护逻辑大小与磁盘占用 | 大目录卡顿、重复展开、聚合错误、链接循环 | 每个目录显示递归总大小、自身大小、占比、项目数、类型与扫描状态；子目录可逐级展开；10 万节点滚动无感；硬链接/符号链接/Junction 不重复计入；可定位到具体文件 |
| A3 | 大文件清单与完整路径视图 | P0 | 单独发现占用空间最多的文件，并显示所属目录和完整路径 | Rust 扫描时增量维护 Top-N 索引；路径智能折叠、悬停、复制和定位 | 误把大文件当垃圾、重复枚举、界面过长路径溢出 | 默认按大小降序；支持 10/50/100/500 MB 及 1 GB 阈值；支持复制路径、打开所在文件夹和在目录树定位；不得自动勾选删除 |
| A4 | Treemap、条形图、扩展名、Top 文件 | P1 | 通过图形化视图快速发现空间热点，与目录树和大文件清单交叉验证 | Rust 计算树状聚合；前端渲染；NTFS 压缩/稀疏文件需按占用显示 | 大目录卡顿、大文件误导为“可删” | 图表可筛选、钻取；Top 1000 可排序，悬停显示真实大小和占用；点击可跳转目录树或大文件视图 |
| A5 | 只读扫描、暂停、恢复、取消 | P0 | 大扫描可控，不会因误触删除 | Rust 异步任务、工作窃取、取消令牌、分页流式渲染 | 取消后状态不一致 | 支持断点恢复；取消后显示已扫描范围和部分结果，不显示虚假完成 |
| A6 | 系统临时文件识别 | P0 | 释放低风险临时空间 | `GetTempPathW`、`%TEMP%`、`C:\Windows\Temp`；按最后修改时间、文件句柄占用判断 | 进程仍在用、共享 temp 冲突 | 只删可删除文件；占用项列出进程；释放量与文件系统占用一致 |
| A7 | 回收站枚举与清理 | P0 | 释放已知用户确认的空间 | Shell32 `SHQueryRecycleBin`、按 SID 隔离、回收站元数据 | 多用户删除、配额差异 | 显示每用户可回收量；管理员仅清理本人或经同意的明确目标 |

| A16 | 一键清理占用检测与失败跳过 | P0 | 不强制结束浏览器、IDE、游戏等用户程序 | 进程锁检查、Restart Manager、超时与重试预算、失败聚合 | 锁定判断误报、跨进程占用、等待过长 | 运行中应用缓存默认提示关闭或跳过；文件占用、权限不足、链接循环、路径过长时跳过并记录；不阻塞队列 |

**MVP 验收不以“释放 GB 数”为唯一目标。** 更重要的是：默认一键清理不会因用户缺乏专业知识而删除用户文档、应用数据库、系统组件或当前运行中应用的必要数据；每个删除动作前后可用空间变化稳定；删除后浏览器、Office、Teams、微信、开发工具等常用应用可正常启动；扫描、删除和恢复日志可逐条回溯。BleachBit 的命令行与可扩展清理规则说明规则化引擎有价值 [1]，但 MVP 不需要实现社区规则市场；先建立安全模型，再扩大规则覆盖面。

## 4. MVP+ 应建立系统级清理和恢复能力，但深度空间必须通过官方 API 释放

**MVP+ 的核心不是增加更多“可删目录”，而是把高风险系统空间交由 Windows 自身机制处理，并为常规清理建立备份与恢复基础。** 这一阶段应优先覆盖 Windows 更新、组件存储、重复文件和报告，而不是扩展注册表或启动项优化。

TreeSize 提供详细报告、PDF/Excel/CSV 导出和大文件、重复文件查找 [2]；WinDirStat 同样支持扫描导出 [3]；BleachBit 提供文件粉碎和空闲空间覆写 [1]；PrivaZer 提供不可逆覆写并按存储类型适配算法 [4]。这些能力应拆成独立、可解释的子模块，不能合并成“深度清理”。

MVP 的目录空间树与大文件清单解决“宏观比较目录、逐级下钻并列出最大文件”的基础体验；MVP+ 的大文件、旧文件、扩展名和重复文件能力，则在此基础上增加时间、归属、关联应用和重复关系维度，仍属于只读发现，默认不自动删除。

## 5. 1.0 才进入企业治理，重点是审批、审计和可控部署，而不是远程擦盘

**企业版的核心价值是“受控复制运维能力”，不是扩大删除权限或自动执行更多危险动作。** 1.0 应让管理员定义策略、审阅例外、调度只读扫描，并能够审计每一步执行；任何破坏性操作仍须设备端确认。

TreeSize Professional 已把计划扫描、比较报告、阈值告警、导出和命令行能力作为专业功能 [2]；Patch My PC 的批量卸载、自动更新和静默更新说明应用生命周期操作具有独立价值 [5]。本产品不应简单照搬，而应把相同能力放在“先审批、后执行、全程可审计”的企业治理模型中。

## 6. Rust 应作为统一核心，但不应重写已有且成熟的操作系统接口

**Rust 是扫描、规则、CLI、跨平台测试和审计流水线的合适选择，但 Windows 的组件存储、安装、更新和恢复仍应使用官方工具或官方 API。** 推荐按职责拆分，而不是构建一个巨大且高度提权的单体 GUI。

### 6.1 推荐分层架构

```text
┌────────────────────────────────────────────────────┐
│ UI：Rust + WebView / 原生壳；只读默认进程          │
└────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────┐
│ 域层：扫描模型、规则引擎、风险决策、恢复工作流      │
└────────────────────────────────────────────────────┘
┌──────────────────┐  ┌───────────────────────────────┐
│ Rust Core：FS/NTFS│  │ Action Runner：回收站、备份、删除 │
└──────────────────┘  └───────────────────────────────┘
┌────────────────────────────────────────────────────┐
│ Admin Helper（按需提权）：DISM、WMI、服务、VSS、UAC │
└────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────┐
│ Adapters：PowerShell、winget、C++/C# 系统组件桥接    │
└────────────────────────────────────────────────────┘
```

Rust 适合文件系统枚举、长路径与错误类型、并发任务、规则匹配、哈希计算、CLI、配置校验、结构化日志、SQLite/备份索引和跨配置测试。推荐 crate 方向包括 `windows`、`windows-service`、`ntapi`（仅在明确边界内使用）、`rustix`/`rustc-hash` 或成熟哈希库，以及 SQLite 封装。具体依赖必须按审计报告冻结，不能仅因“流行”引入。

**目录树和大文件视图应共享同一次扫描索引，而不是分别枚举磁盘。** 扫描引擎增量生成节点树和文件索引；目录树负责“空间在哪里”，大文件视图负责“哪些文件最大”，清理视图负责“哪些可以安全删除”。三者通过统一的 `ScanIndex` 互相跳转：目录树节点可以打开该目录在大文件视图中的结果，大文件路径可以反向定位到目录树节点。目录大小必须按逻辑大小与磁盘占用分别维护，并在聚合完成后统一计算；大文件索引不得把目录、硬链接重复项或跨卷链接目标重复计入。

C++ 只适合极少数需要最新 Windows 内部 API、NTFS 结构或设备 I/O 控制且 Rust binding 不成熟的模块，并通过稳定 ABI 和 fuzz 测试隔离。C#/.NET 适合快速构建启动项、计划任务、MSI/ARP、Store 应用和 Shell 集成原型，但最终应评估双运行时体积、启动速度和权限模型；若收益不明显，则统一交给 Rust + 官方工具。

PowerShell 适合包装已有官方维护逻辑，包括 Windows 更新状态、CIM/WMI、计划任务、服务、Windows Defender 状态、存储感知和 DISM。它能降低自研风险，但必须启用 Constrained Language、签名、允许清单、超时和输出 Schema；不允许拼接不可信路径执行任意命令。

### 6.2 各技术的明确分工

| 能力 | 推荐实现 | 理由 | 不应如何做 |
|---|---|---|---|
| 空间分析、NTFS 枚举、链接识别 | Rust + Windows API/USN | 并发、内存安全和类型化错误处理适合核心扫描 | 自行解析所有 NTFS 结构 |
| 大小、占用、硬链接去重 | Rust 核心 + `ByHandleFileInformation` | 用 FileIndex 和 VolumeSerialNumber 去重 | 仅按路径或文件名去重 |
| 系统临时、回收站、Shell 清理 | Rust + Shell32/COM | 保持用户和系统语义一致 | 绕过 Shell 直接批量删系统目录 |
| 浏览器/应用缓存 | 声明式规则 + 进程检测 | 版本变化快，适合配置迭代 | 在 Rust 二进制中硬编码脆弱路径 |
| Windows 更新/WinSxS | DISM API/CLI、PowerShell、Windows Update API | 由系统判断组件依赖与可清理范围 | 手工删除 `WinSxS` 或 `SoftwareDistribution` 内部文件 |
| 启动项、服务、任务计划 | C# 原型后下沉 Rust/COM，或通过 PowerShell | API 稳定且语义复杂 | 默认提供“一键禁用” |
| 安装、升级、卸载 | winget CLI/REST/COM，按能力可用 | Patch My PC 证明应用更新是独立价值 [5] | 自研安装器捆绑第三方软件 |
| 卷影复制 | Windows VSS COM/IVssBackupComponents | VSS 为备份和一致性而设计 [9] | 用于普通缓存删除或当作文件恢复主方案 |
| 隐私擦除 | Rust 可选模块 | 只处理明确选定文件，边界清晰 | 默认全盘覆写或宣称 SSD 安全擦除 |

## 7. 安全边界应以“系统仍可运行、用户数据不丢失、操作全程可回滚”为验收前提

**恢复能力不是清理的附属功能，而是高风险删除的前置条件。** 普通删除、永久删除和系统组件清理必须采用不同风险路径：前者可以依赖回收站，后两者必须有还原点、备份或明确告知不可逆。

WinDirStat 本身只提供打开、移动和删除等文件操作 [3]，而 BleachBit 明确将文件粉碎和空闲空间覆写作为独立、可选择的能力 [1]。这说明安全擦除可以存在，但不能与“清理缓存”使用同一默认行为。

| 恢复方式 | 适用对象 | 保留期 | 能力 | 限制 |
|---|---|---|---|---|
| 回收站 | 用户明确选择的一般文件 | 按回收站配额 | 还原到原位置 | 跨卷移动后可能失去原元数据；管理员权限与 SID 隔离 |
| 产品备份区 | 默认高风险文件、规则目录、部分注册表项 | 7/30/90 天可配置 | 单文件、批量、版本恢复 | 不能替代完整备份；需要配额和加密 |
| 系统还原点 | WinSxS、组件、系统设置、驱动 | 受系统保护配额限制 | 回滚系统状态 | 不保护个人文件，可能占用 C 盘空间 |
| VSS 快照 | 企业高风险维护窗口 | 计划保留，默认不常驻 | 提供一致视图和短期恢复 | 不是完整备份，可能被系统自动清理 |
| 外部备份 | 用户文档、代码、邮件、虚拟机 | 由用户/企业策略决定 | 完整业务连续性 | 本产品仅提供清单和建议，不替代备份软件 |

PrivaZer 将“irreversible cleanup”单独标示，说明用户必须知道动作不可逆 [4]。本产品应把删除模式设置成显式枚举：`recycle`、`backup_then_delete`、`delete_only`、`shred_once`，不允许使用模糊的“安全清理”标签掩盖差异。

### 7.1 恢复工作流

1. 用户确认前，显示“可撤销/部分可撤销/不可撤销”以及恢复路径；
2. 普通缓存默认 `recycle`；
3. 系统缓存、浏览器 profile 和已识别应用数据默认 `backup_then_delete`；
4. WinSxS 等系统组件默认 `create_restore_point + create_vss + review`；
5. 执行中按卷提交原子批次，记录每个文件的原路径、大小、哈希、ACL、硬链接关系、回收站 ID、备份 ID 和删除时间；
6. 失败后停止同批剩余操作，但不自动回滚已经成功的系统组件变更；
7. 完成页显示“实际释放”“未释放”“被占用”“跳过”“已备份”“可恢复”六类结果；
8. 任何 7 天内执行都可从日志定位到备份、还原点或 VSS 记录。

## 8. 白名单、禁止路径和二次确认必须写死在引擎中，不能由普通用户配置降级

**真正不可恢复或会导致系统不可用的对象，应禁止产品自动选择，而不是仅通过风险提示让用户自行判断。** 白名单可以扩展，禁止列表不可被低权限配置覆盖。

### 8.1 默认禁止删除

- `C:\Windows`、`C:\Windows\system32`、`C:\Windows\SysWOW64` 及其直接文件；只允许系统 API/规则处理明确可清理子目录，且规则逐条签名。
- `C:\Windows\WinSxS` 直接文件、`C:\Windows\Installer` 直接文件、`C:\Windows\SoftwareDistribution` 内部文件、`C:\Windows\Logs\CBS` 内部文件。
- `C:\Program Files`、`C:\Program Files (x86)`、`C:\ProgramData` 的软件本体、数据库、许可证和设置；仅允许按应用文档清理明确命名的缓存目录。
- 系统卷信息和根目录的 `System Volume Information`、卷影副本、`$Recycle.Bin`、`$Extend`、`Recovery`、EFI 分区、BitLocker 元数据。
- 页面文件 `pagefile.sys`、休眠文件 `hiberfil.sys`、系统崩溃转储；仅允许在明确告知且管理员确认后调用系统接口修改休眠状态。
- `%USERPROFILE%` 下的一线文档目录：`Desktop`、`Documents`、`Pictures`、`Music`、`Videos`、`Downloads`、`OneDrive`、`iCloudDrive`、`Dropbox`、坚果云等；不得按年龄自动删除。
- 浏览器 profile 中的 `Login Data`、`Cookies`、`Web Data`、`Bookmarks`、`Favicons`、`Extensions`、sync 数据库、密码、证书和钱包；用户主动选择时只删除缓存、下载记录、历史记录等明确类别。
- 邮件和协作应用数据：Outlook OST/PST/Draft、Thunderbird profile、Mail、People、Teams/Slack 消息数据库、微信/QQ 聊天文件和媒体库默认全部不删；用户逐文件夹确认后，才允许删除缓存。
- 代码与工程目录：`node_modules`、`.git`、`.venv`、`venv`、`.nuget`、`.m2`、`.gradle`、Cargo registry、Docker/Containerd 镜像与数据、WSL 虚拟磁盘、虚拟机、游戏存档和本地模型文件。产品可发现其占用，但不得把整个目录当作垃圾。
- 加密容器、恢复分区、可移动介质、网络共享、WSL/Linux 文件系统、光驱和未就绪卷。
- NTFS 保留名称 `CON`、`PRN`、`AUX`、`NUL`、`COM1–COM9`、`LPT1–LPT9`，以及会被解释为设备名的变体。Windows 命名文档明确警告这些名称不可用 [9]。

### 8.2 默认白名单和二次确认

| 对象 | 默认动作 | 触发条件 |
|---|---|---|
| 系统临时目录 | 可清理普通缓存 | 正在使用、文件锁或属系统进程时保留 |
| 当前用户 `%TEMP%` | 可清理 | 文件正在使用或规则排除时保留 |
| 回收站 | 可清理 | 多用户、网络路径、配额异常时二次确认 |
| Windows 错误报告、缩略图缓存、Shader/DX 缓存、缩略图数据库 | 可清理 | 服务繁忙或重建代价过高时说明影响 |
| 传递优化缓存、Windows 更新下载缓存 | 受控清理 | 更新服务正在下载/安装、服务状态异常时禁止 |
| 日志与诊断数据 | 受控清理 | 只删可重建内容；安全/合规要求保留时禁止 |
| 浏览器缓存、站点数据、表单、历史 | 逐项确认 | 浏览器运行中需关闭或按进程策略处理 |
| 应用缓存、日志、临时下载、崩溃报告 | 逐项确认 | 必须识别应用、profile、运行状态和官方清理建议 |
| 大/旧/重复文件 | 仅发现，不默认选择 | 用户显式选择后进入删除审批 |
| WinSxS、Installer、可选功能、系统组件 | 受控系统维护 | 高风险审批、还原点/VSS 前置，并明确可能不可回退 |
| 软件卸载 | 逐项确认 | 识别重启需求、依赖项和退出码 |
| 休眠文件、系统还原、VSS、SSD 覆写 | 专家模式 | 明确告知数据销毁、系统能力和设备影响 |

### 8.3 文件类型与状态规则

可执行程序、驱动、系统库、注册表配置、许可证、数据库、容器镜像、虚拟机磁盘、OST/PST、浏览器 profile 主数据库和凭据文件不应被路径通配符命中。扩展名只能作为分类线索，不能作为可删除判定依据：`.log` 可能仍在写入或属于审计要求，`.tmp` 可能仍在被进程占用，`.db` 可能是应用数据库，`.old` 可能是降级回退材料。

文件锁采用三重检查：尝试打开 `FILE_FLAG_DELETE_ON_CLOSE`；读取共享锁状态；必要时查询 Restart Manager。任何不确定状态均按“保留”处理。删除成功后必须校验目标不存在；若 Shell 移动到回收站，则记录回收站记录而不是假定物理删除完成。

## 9. 权限必须最小化和双进程化，UAC、VSS、长路径和链接处理都不可绕开

**产品默认以标准用户运行；只有访问系统目录和执行系统变更时，才按需提升到独立助手进程。** 提权不应继承给扫描 UI、规则下载或报告导出。

UI 默认以普通用户运行；扫描用户目录无需 UAC。访问受限系统目录、执行系统清理、创建还原点或 VSS 快照、卸载软件、调用 DISM 时，才启动签名管理员助手。助手必须使用独立清单、最小能力，并通过管道或 RPC 使用低权限协议。

安装程序不应捆绑广告、工具栏、驱动或第三方修改器；默认写入用户可审计的安装目录，并支持便携模式与受控企业安装。第一次启动时明确说明：产品不会自动发送文件内容、安装软件、修改安全设置、清理还原点或永久删除文件。

### 9.1 关键安全控制

| 控制 | 要求 |
|---|---|
| 最小权限 | UI 默认标准用户；管理员助手按需启动，不常驻、不继承完整桌面权限 |
| UAC | 不使用 `autoElevate`；不修改 Consent Policy；提权请求明确说明范围 |
| 路径规范化 | 展开短名、相对路径、挂载点、卷 GUID、Junction/ReparsePoint；比较时同时检查物理路径和链接目标 |
| 长路径 | 全链路使用 `\\?\` 或启用长路径；限制输入长度，规范化不制造缓冲区问题；保留原始显示名 |
| 符号链接 | 默认不跟随指向系统根、其他卷、网络或高权限目录的链接；发现时告警，不把目标重复计入当前目录 |
| 硬链接 | 通过 VolumeSerialNumber + FileIndex 识别；物理删除一次，逻辑删除保持引用计数正确 |
| Junction/挂载点 | 按“进入当前卷/跨卷”分层；默认只分析当前卷，跨卷需显式选择 |
| 循环 | 文件系统对象 ID + 路径预算 + 深度限制 + 计时器；不能仅靠 MAX_PATH |
| 文件占用 | 通过共享模式和 Restart Manager 检查；删除前再校验；失败后跳过，不强制结束进程 |
| 杀毒误报 | 代码签名、官方发布页、哈希、稳定下载服务器、排除项说明；不要求永久关闭 AV |
| 恶意路径 | 校验 UNC、ADS、设备路径、保留名、尾部点/空格和大小写变体；不使用拼接后的路径直接访问 |
| 依赖链 | 固定版本并校验哈希；规则必须签名；禁止运行时从不受控 HTTP 拉取可执行代码 |

微软文档指出，Windows 10 1607 之前最大路径通常为 `MAX_PATH` 260 字符；更高版本可通过注册表或组策略放宽，且 `\\?\` 前缀会绕过部分字符串解析 [9]。因此，产品不能依赖默认 `MAX_PATH`，也不能无条件展开所有链接。

VSS 是允许应用程序在卷持续写入时执行备份的 COM API 框架 [10]。本产品可调用 VSS 获取一致性快照或支持企业备份，但不应在每次普通扫描时创建快照。系统盘空间不足时，VSS 还可能被系统自动清理；因此，VSS 只能作为短期恢复补充，不能替代完整备份。

## 10. 默认离线是隐私底线，遥测只能作为可选的诊断授权

**扫描过程本身就是敏感数据处理过程，产品不能把“磁盘清理”变成隐蔽的数据采集器。** 默认应完全离线；任何诊断、错误报告、规则更新或企业审计都必须在界面上明确说明数据范围、用途、保存期限和关闭方式。

PrivaZer 把“零跟踪、零遥测、零广告”作为产品承诺 [4]，说明隐私清理工具更需要避免言行不一。本产品不应默认上传文件名、目录结构、应用使用痕迹或扫描结果。

| 类别 | 默认 | 用户授权后 | 禁止 |
|---|---|---|---|
| 扫描范围、目录树 | 仅本地 | 可导出本地报告 | 后台上传完整路径树 |
| 规则匹配 | 仅本地 | 仅上传规则 ID 和命中摘要 | 上传文件名、文件内容或浏览历史 |
| 错误诊断 | 本地崩溃摘要可选 | 用户选择后上传最小 dump/日志包 | 自动上传文档、密码、浏览器 profile |
| 产品更新 | 可选检查 | 官方签名增量、规则与依赖哈希 | 静默安装第三方组件 |
| 企业审计 | 关闭 | 管理员开启最小数据集 | 收集屏幕、键盘、账号、个人文件 |
| 崩溃信息 | 关闭 | 本地打包或上传匿名 ID、版本、错误码 | 包含路径、用户名、IP、文件哈希原文 |

实现上，遥测必须经过事件同意、范围裁剪、数据最小化、本地脱敏、哈希化标识、传输加密、保留期、删除入口和审计日志。企业审计默认采用设备拉取，不使用远程命令。若用户拒绝，功能必须继续可用；产品不得因关闭遥测而限制本地扫描、清理或恢复。

中国个人信息保护、数据出境、未成年人信息、企业员工数据及跨境场景，由部署方法务结合具体客户和数据处理角色确认；本报告只提出产品架构原则，不替代法律意见。

## 11. 验收必须同时覆盖空间准确性、删除安全性、性能、隐私和故障恢复

**单靠“清理后释放多少空间”无法证明产品安全；验收必须同时证明扫描准确、边界有效、操作可回滚、性能和隐私均达到要求。** 基准测试环境应覆盖 Windows 10/11 的 64 位主流版本、NTFS、管理员与非管理员、SSD/HDD、有无长路径、有无链接、有无 BitLocker 和系统还原等组合。

### 11.1 核心质量指标

| 指标 | 目标 |
|---|---:|
| 扫描准确性 | 与文件系统占用和已验证参考扫描器 Top 目录差异 ≤1%；差异必须有解释 |
| 链接处理 | 100% 识别硬链接、符号链接、Junction 和挂载点；不重复计入 |
| 目录树准确性 | 任一目录递归总大小等于其子目录和文件聚合大小；10 万节点滚动与展开无明显卡顿 |
| 大文件视图 | 默认按大小降序；切换阈值或排序时不重新扫描；Top 1000 筛选、复制路径、定位目录树均稳定可用 |
| 跨视图一致性 | 目录树、大文件视图和清理视图的相同文件大小、占用、硬链接及锁定状态完全一致 |
| 安全边界 | 默认配置下命中禁止路径、系统目录、保留名、浏览器凭据和邮件数据的用例 100% 阻断或二次确认 |
| 文件锁 | 模拟占用场景时，100% 不强制结束关键进程；可删除项与保留项结果一致 |
| 回收站恢复 | 单文件、批量、长路径、特殊字符和跨卷场景恢复成功率 ≥99.9% |
| 性能 | 100 万个文件扫描 ≤10 分钟；UI 无 1 秒以上无响应；CPU/磁盘 I/O 可限速 |
| 内存 | 冷启动常驻内存 ≤250 MiB；扫描 500 万文件峰值 ≤2 GiB；具体值随硬件基线调整 |
| 稳定性 | 连续扫描、取消、重启、网络中断、权限变化 24 小时压测无崩溃或数据损坏 |
| 可审计性 | 每个动作都有规则 ID、时间、权限、路径、大小、备份 ID、退出码和结果 |
| 隐私 | 默认无网络请求；报告可脱敏；遥测关闭后不再产生外发事件 |
| 兼容与部署 | 支持 x64；ARM64 在 1.0 前完成可运行验证；安装包签名可验证 |
| 恢复验证 | WinSxS、临时文件、应用缓存和浏览器缓存高风险用例均能通过备份/还原点恢复 |

### 11.2 分层测试策略

**单元测试**覆盖路径规范化、glob/regex、规则匹配、哈希、JSON Schema、ACL 复制、回收站记录、硬链接和文件锁状态。

**集成测试**使用真实 NTFS 镜像和可重复构造的目录树，包括 260 字符以上长路径、尾部空格/点、保留名、8.3 短名、Junction、跨卷链接、硬链接、稀疏文件、压缩文件、加密文件和不可访问文件。

**系统测试**验证 UAC、管理员助手、服务状态、Windows 更新下载中、系统还原开启/关闭、BitLocker、OneDrive 占位、脱机文件、网络驱动器和不同用户配置。

**应用兼容性测试**至少覆盖 Edge、Chrome、Firefox、微信、QQ、Teams、Outlook、OneDrive、Steam、Epic、Visual Studio、JetBrains IDE、Docker/WSL 等常见场景，但不能伪造其官方支持声明。

**性能基准**使用 10 万、100 万、500 万文件及大量小文件场景，记录冷扫描、增量扫描、Treemap 构建、导出、删除和恢复时间。测试前执行一次文件系统缓存预热；结果按 P50/P95/P99 报告，而不是只报告平均值。

**故障注入**覆盖磁盘满、磁盘只读、卷脱机、取消、崩溃、进程占用、符号链接循环、规则签名失效、提权被拒绝、VSS 不可用、DISM 非零退出码、winget 不存在、卸载重启挂起和备份区配额不足。

**界面专项测试**覆盖目录树逐级展开/折叠、排序后保持展开状态、超长路径折叠与悬停、超大目录虚拟滚动、扫描中途增量更新、取消后继续浏览已完成目录、切换扫描根目录、大文件阈值切换、复制路径、打开所在文件夹、从大文件跳转到目录树，以及目录树和大文件视图共享同一扫描索引时的并发更新。

**安全测试**包括规则注入、路径穿越、链接指向系统目录、UNC/ADS、特权助手欺骗、UI 自动化绕过、本地提权、签名验证、依赖替换、遥测端点数据泄露和 AV 误报。每次发布前进行 SAST、依赖漏洞扫描、签名验证和至少一轮手动权限复核。

### 11.3 上线门禁

MVP 上线前必须通过：默认禁止项测试、白名单优先级测试、长路径和链接测试、所有高风险动作恢复演练、管理员/标准用户权限矩阵、本地离线运行、报告脱敏、目录树逐级聚合准确性、大文件视图排序与路径定位，以及至少两轮应用兼容性测试。

MVP+ 上线前还必须通过：DISM 兼容矩阵、WinSxS 只读分析、VSS/还原点恢复、备份配额、重复文件硬链接测试、文件锁测试、崩溃恢复和跨视图数据一致性测试。

1.0 上线前必须通过：企业策略优先级、签名规则、CLI 退出码、计划任务、审计日志、无网络诊断包、远程只读会话审批、杀软误报和大规模部署演练。

任何导致系统不可启动、用户文档丢失、浏览器登录态无提示清除、绕过 UAC 或删除系统关键文件的缺陷，均为 P0，不得通过发布评审。

## 12. 最终决策：先交付可信扫描和受控清理，再扩展到系统维护与企业治理

**建议立项，但产品范围应严格收敛为“Windows C 盘空间分析与受控清理”。** 核心用户价值不是扫描项数量，也不是宣称的 GB 释放量，而是让普通用户通过默认一键清理安全释放常见缓存空间，同时通过目录空间树和大文件路径清单准确理解空间占用，并为专业用户提供可解释的标准清理与高级维护能力。产品替普通用户完成判断，但所有高风险动作仍交给官方机制、恢复前置条件和明确确认流程。

产品界面应围绕三个相互关联的核心视图设计：目录空间树负责逐级定位目录和文件；大文件清单负责按大小降序并展示完整路径；可清理项负责按规则分类并执行受控清理。三个视图共享同一次扫描索引，可以从目录节点跳转到其大文件列表，也可以从大文件路径反向定位到目录树中的具体位置。默认一键清理应作为 MVP 首屏主入口：用户点击后自动完成扫描、类别准入、占用检测、自动清理和结果报告，但默认只处理回收站、系统临时文件、浏览器缓存、缩略图缓存、应用日志及明确可重建的应用缓存等高置信度低风险项；用户文档、应用数据库、系统组件、更新缓存和大/旧/重复文件不进入默认队列。标准模式允许用户主动选择更多缓存和系统受控项；高级模式才开放 WinSxS、还原、休眠、永久删除和覆写等高风险能力。Rust 适合承担扫描、规则、CLI、并发、配置、日志和备份索引；Windows API、DISM、WMI/PowerShell、winget、VSS 和系统 Shell 应各自负责其官方职责。C++ 仅在确有必要时用于 NTFS/设备 I/O 适配，C# 可用于 Shell 和系统管理原型；二者都不应成为日常清理的默认路径。

建议排期顺序为：

1. **MVP：**磁盘总览、逐级钻取式目录空间树、大文件清单与完整路径、只读空间分析、风险分级、默认一键清理、浏览器/应用缓存、系统临时文件、回收站、预览、结果报告和回收站恢复；
2. **MVP+：**大/旧/重复文件、应用清单、受控卸载、Windows 更新只读分析与受控清理、WinSxS/DISM、PDF/HTML/CSV/JSON 报告、备份区、可选覆写；
3. **1.0：**企业策略、审计、CLI、计划任务、VSS、远程只读诊断和代码签名治理。

三个阶段最重要的共同约束是：默认一键清理只处理高置信度低风险可恢复项，目录树和大文件视图不自动删除用户文件，空间分析不自动删除，系统维护不直接改写组件存储，永久删除不成为默认，系统还原点不自动清理，企业管理员批准也不能绕过安全和一致性限制。

本报告基于截至 2026 年 9 月 24 日可查的官方产品页面、微软官方文档和已公开项目状态。由于 BleachBit、PrivaZer、TreeSize、WinDirStat、Dism++ 和 Patch My PC 的版本、收费层级和功能细节会持续变化，发布前应按实际目标版本重新执行功能核对。部分官方页面未公布当前精确内部版本号，不应据此编造“最新版本”。
